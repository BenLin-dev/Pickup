# Locales — how the site speaks five languages

One file per language. Nothing else on the site holds copy that isn't routed
through here.

```
src/i18n/
  index.js        the runtime: locale resolution, t(), tr(), switching
  locales/
    en.json       the message catalogue — GENERATED, do not hand-edit
    fr.json       French
    es.json       Spanish (European)
    it.json       Italian
    de.json       German
```

## The English sentence is the key

```json
{
  "Book Now": "Réserver",
  "Airport transfers in Guangzhou": "Transferts aéroport à Canton"
}
```

There are no dotted keys like `home.hero.title`. The key **is** the English
source string, which means:

- Editing English copy can never leave a stale key behind, because there is no
  second vocabulary to keep in sync.
- A message with no entry in the active language renders as its English self.
  A half-finished translation degrades to English — never to a blank element,
  never to `undefined`.
- Identical English strings collapse into one entry, so `Book Now` is
  translated once no matter how many components render it.

`en.json` is generated by `scripts/extract-i18n.mjs`, which walks the exported
data structures and every `t('…')` call in `src/`, then filters out anything
that isn't copy (slugs, paths, URLs, e-mail addresses, hex colours, currency
codes). It runs automatically as the first step of `npm run build`, so a new
string can never be missing from the catalogue.

```bash
npm run i18n      # regenerate en.json + report translation coverage
```

## Adding or changing copy

1. Write the English where it belongs — in a data module or in a template.
2. In a **template**, wrap it: `{{ t('Your new sentence') }}`, or
   `:alt="t('…')"` for an attribute. Add `import { t } from '@/i18n'`.
3. In a **data module**, wrap the export once: `export const fleet = tr([...])`.
   `tr()` deep-walks the structure and translates every string leaf it finds in
   the catalogue; the technical strings it doesn't recognise come back
   untouched, so no allow-list is needed.
4. Run `npm run i18n`, then add the new key to `fr/es/it/de.json`.

A **prop default** is the one place the scanner is blind. `<script setup>` hoists
`default:` to module scope, so `default: t('Videos')` throws `ReferenceError`
during prerender — the component has to keep the English literal and translate
at the render site (`{{ t(title) }}`), which leaves no `t()` call for the
scanner to find. `scripts/extract-i18n.mjs` therefore keeps a `MANUAL_KEYS`
list for these, and prints a warning if a prop default shows up that is not in
the catalogue. If you add one, add its English to `MANUAL_KEYS` too.

Never edit a **key** in a translation file. A key that differs by one character
— a different dash, a straight apostrophe instead of `’` — silently stops
matching and the page falls back to English.

## Switching languages

`resolveLocale()` runs **once, at import time**, before the app mounts:

1. the visitor's own choice, remembered in `localStorage`
2. the browser's ordered language preferences
3. English

A `zh-CN` or `pt-BR` visitor gets English rather than the nearest neighbour.

The switcher in the header calls `setLocale()`, which stores the choice and
reloads the page — every data module is translated as it evaluates, so
re-running them is what re-renders the site. There is no reactive plumbing, and
no way for one module to be in a different language from another.

Prerendering runs in Node, where there is no `window`, so `resolveLocale()`
returns English and the static HTML stays English — which is also the version
Google indexes. Ads landing pages and every existing URL are unaffected.

## What stays English on purpose

- **Long-form guides** under `/blog` and the **privacy policy / terms**. Legal
  wording names a data controller and a governing law; a machine translation
  there is a liability, and the reader who gets that far is already committed.
- **Config, not copy**: phone number, e-mail, `addressLine` (it feeds JSON-LD),
  integration keys.
- **The pre-filled WhatsApp message.** The booking inbox is read by the
  operator, and a message that arrives in a language the operator cannot triage
  is worse than one that arrives in English.
- **SEO keyword anchor blocks** in the footer — English search terms.

## Images

Nothing on the site swaps images per language. The ones that carry baked-in
English text are listed in the handover notes; the main ones are
`public/images/og-image.jpg` (wordmark + tagline + "Get a free quote"), the
three `public/videos/*.jpg` posters ("CantonPickup" watermark) and the ten
generated WhatsApp-style screenshots in `public/images/reviews/*.png`.
